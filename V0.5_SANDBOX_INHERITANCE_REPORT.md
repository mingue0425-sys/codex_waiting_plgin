# Codex Snooze v0.5 sandbox inheritance report

Backend B was tested with a benign parent → child → grandchild → detached
descendant fixture. Each role records its PID, parent PID and session ID and
the detached descendant attempts one write to a temporary sibling directory.

The normal Codex turn emitted a command item for
`/bin/zsh -lc 'python3 inheritance_fixture.py parent'`, but the temporary
fixture files were not visible to the probe process. Consequently:

```text
Codex descendant fixture exercised = false
Codex sandbox inheritance = UNKNOWN
Codex approval integrity = UNKNOWN
```

The probe also runs a host-only reference. The host reference showed a
detached descendant with `ppid=1` and a successful sibling write. That result
is explicitly marked `is_codex_evidence=false`; it demonstrates why a local
subprocess test cannot prove that a Codex sandbox survives parent exit.

No `launchd`, external daemon or controller-spawned supervisor was used in the
candidate path. The controller-spawn and external-daemon flags are false in
[results/v0.5/process-inheritance.json](results/v0.5/process-inheritance.json).

Until a normal Codex terminal command produces observable parent/child
fixtures and the same boundary is measured after detach, Backend B remains
experimental and is never selected automatically.
