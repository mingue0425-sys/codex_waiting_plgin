# Codex Snooze v0.4 agent benchmark

Evidence: [results/v0.4/agent-benchmark.json](results/v0.4/agent-benchmark.json)
and the explicit workload evidence in
[results/v0.4/agent-benchmark-handoff.json](results/v0.4/agent-benchmark-handoff.json).

The comparison is directional: the baseline is a normal Codex terminal
workload, while the Snooze run is an explicit dynamic-tool handoff workload.
It measures whether the model continues generating activity during the long
job wait. It does not compare equivalent prompts closely enough to support a
token-cost claim.

| Measure | Baseline | Explicit Snooze workload |
|---|---:|---:|
| Wall time | 29.801 s | 30.989 s |
| Turns | 1 | 2 |
| Tool calls | 2 | 1 handoff call |
| Model events during long-job wait | not applicable | 0 |
| Continuation | not applicable | true |
| Token usage notifications | available in baseline output | 0 during wait |
| Token savings | not measured | `NOT_CLAIMED` |

The explicit handoff workload passed its continuation conditions and the model
was idle during the 12-second long-job interval. The owned App Server did not
emit token-usage notifications in that short benchmark, so the benchmark
records telemetry as `UNKNOWN` and makes no savings claim.
