# Codex Snooze v0.5 native handoff E2E

The native probe created a disposable workspace containing a 16-second
heartbeat fixture and asked the normal thread tool to run exactly
`python3 fixture.py`. It then inspected the protocol at the ten-second
boundary, queried `thread/backgroundTerminals/list`, and interrupted the turn
only after the boundary. It never called `command/exec`, `process/spawn` or
`thread/shellCommand`.

The result is [results/v0.5/native-terminal-e2e.json](results/v0.5/native-terminal-e2e.json).
The turn reached `turn/completed` with `status=interrupted`, but no
`commandExecution` item, fixture heartbeat, native background handle or
completion item was observed. The model produced a textual acknowledgement
without issuing the requested terminal call.

Therefore:

```text
normal tool execution = not proven for this exact fixture
10S_HANDOFF = UNKNOWN
JOB_SURVIVAL = UNKNOWN
MODEL_IDLE_DURING_WAIT = UNKNOWN
COMPLETION_DETECTION = UNKNOWN
AUTO_CONTINUATION = UNKNOWN
```

The zero model-event count after the threshold is not promoted to a model-idle
PASS because no command was owned during that interval. The same-thread
continuation chain is also not started when the prerequisite native ownership
is absent.

The event summary still records the authoritative protocol methods and their
request/notification ordering. Repeating this probe with an observable normal
terminal item is required before Backend A can move beyond UNKNOWN.
