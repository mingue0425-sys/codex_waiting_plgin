# Codex Snooze v0.4 explicit handoff report

The model-backed explicit handoff chain passed on the Snooze-owned App Server
path. This result covers the handoff protocol and continuation behavior. It is
reported separately from the failed sandbox and approval parity gate.

## Primary ten-second run

Evidence: [results/v0.4/handoff-e2e.json](results/v0.4/handoff-e2e.json).

| Check | Result |
|---|---|
| Requested threshold | 10 seconds |
| Fixture duration | 12 seconds |
| Explicit named handoff tool | PASS |
| Structured `DETACHED` marker | PASS |
| First turn status | `interrupted` |
| Job after turn end | PASS |
| Job result | `COMPLETED`, exit code 0 |
| Model events while waiting | 0 |
| Continuation thread | same thread |
| Final result token | PASS |
| Fixture run count | 1 |
| Duplicate command guard | PASS |

The first turn returned control after the marker, while the detached
supervisor continued to collect heartbeats and wrote the durable result. After
completion, the controller routed a new continuation turn on the recorded
thread. The final response included the fixture token and the fixture's run
count remained one.

## Result and stale propagation

The failure scenario in [results/v0.4/failure-e2e.json](results/v0.4/failure-e2e.json)
used the same explicit flow with a fixture exit code of 7. The result preserved
`FAILED` and exit code 7, and the continuation reported
`FAILURE_STATUS=EXIT_7` without rerunning the fixture.

The stale scenario in [results/v0.4/stale-e2e.json](results/v0.4/stale-e2e.json)
changed a tracked Git source file after handoff and before completion. The
result became `COMPLETED_STALE` with `source_state_changed=true`; the
continuation reported `SOURCE_STATUS=STALE_NOT_VERIFIED` and did not claim that
the current tree had been verified.

## Deterministic coverage

- `handoff-repetitions.json`: 20 of 20 data-plane handoffs completed with one
  fixture run each.
- `threshold-tests.json`: scaled cases corresponding to 9.5, 10 and 10.5
  logical seconds passed. The threshold is a foreground wait limit; it does
  not kill or time-limit the child.
- `shell-handoff.json`: zsh and bash both passed short-command transparency,
  operators, redirection, quoting, Unicode paths and detached completion.
- `tests/test_v04.py`: structured-marker parsing, nested `command/exec` policy,
  approval rejection, short completion, nonzero exit propagation and model
  activity filtering are covered by unit/subprocess tests.

The full evidence does not promote the path to production because the
security gate is independent and currently failed.
