`APP_SERVER_PARTIAL` means that the installed App Server can be reached and
can perform several disposable-thread operations, including an observed
`turn/interrupt`. It does not authorize direct completion injection into a
user's Desktop turn. The production route remains an explicit
`CLI_RESUME_FALLBACK` or `MANUAL_DELIVERY` operation, chosen by the operator.

## Control-plane evidence

The reusable JSON-RPC client in [tools/app_server_probe.py](tools/app_server_probe.py)
records request ids, timestamps, thread and turn ids, responses,
notifications, stderr and bounded redacted values. The App Server probe used
the installed generated v2 schema rather than copied documentation. It
exercised read-only inspection of an existing non-active thread and mutations
only on disposable threads.

The live interrupt harness attempted five timing points. All five runs were
`UNKNOWN` because the model did not invoke the requested terminal command;
therefore no command-level handoff guarantee was inferred from an
interrupt-only API result. The earlier successful E2E remains in
[results/snooze-e2e-history.json](results/snooze-e2e-history.json), alongside
the repeat UNKNOWN outcomes.

## Security decision

Automatic command rewriting is disabled. The supervisor verifies the
canonical JobSpec digest before spawning a child, but that local integrity
property does not prove that a Codex approval engine evaluates the original
command after a hypothetical rewrite. The sandbox probe used only temporary
workspace and sibling paths and did not establish a comparable model result.

No feature flag enables automatic App Server injection, automatic resume,
automatic handoff or PreToolUse rewriting. The 10-second threshold remains a
foreground ownership handoff option for an explicitly submitted CLI job; it
is not a command timeout.

The local token benchmark measured baseline wall time `0.432929 s`, Snooze
foreground return `0.205271 s`, and eventual completion `0.633875 s` for a
0.4-second sleep-and-marker workload. Codex token, model-turn and tool-call
telemetry was unavailable, so no token-savings claim is inferred.

## Answer to the seven control-plane questions

1. A Desktop thread cannot currently be controlled from an external process with verified same-thread identity: **UNKNOWN**.
2. An App Server turn can be interrupted: **PASS**.
3. Supervisor and command survival after that interruption are repeatable enough for direct automation: **PARTIAL**, so the hard gate is closed.
4. Durable completion can be recovered and explicitly retried with duplicate acknowledgement: **PASS** for the local outbox; remote Codex delivery is unproven.
5. Safe delivery while a user is already in a turn: **UNKNOWN/PARTIAL** at the mechanism-acceptance level; no automatic path is enabled.
6. Controller crash and duplicate state corruption: **PASS** for the local J1-J5 fault cases.
7. Sandbox and approval boundaries: **UNKNOWN**, so security gating remains closed.

## Next milestone

The next milestone requires a supported, externally addressable Desktop
thread identity and a receiver acknowledgement contract that can be tested
with real message and turn counts. Until those are available, improvements
should target explicit CLI/manual delivery, evidence collection and recovery,
not automatic interception.
