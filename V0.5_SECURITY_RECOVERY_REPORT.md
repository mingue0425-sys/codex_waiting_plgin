# Codex Snooze v0.5 security recovery report

The v0.4 controller-level `command/exec` boundary is an immutable regression
fact. The temporary fixture wrote both inside the requested workspace and to a
sibling while the request carried a workspace-write policy, and no approval
request was observed. The rerun remains:

```text
CONTROLLER_COMMAND_EXEC = FAIL
SANDBOX PARITY = FAIL
APPROVAL PARITY = FAIL
```

The v0.5 work does not modify that backend or turn the failure into a PASS.

## Normal-thread probe

The v0.5 normal probe asked the owned App Server thread to execute exactly
`python3 fixture.py`. The protocol produced a normal model turn and, in the
security cases, `commandExecution` item start/completion events with a
processId and exit code. The local disposable fixture did not produce its
marker files, and no approval request arrived. The event stream and the local
filesystem therefore cannot be safely treated as one execution namespace.

That observation is recorded as UNKNOWN. A command string and exit code are
not enough to assert that the controller can see the process, inherit its
sandbox, or take background ownership.

## Recovery behavior

The recovery decision is:

```text
normal command execution evidence = observed but unshared
native sandbox parity = UNKNOWN
native approval parity = UNKNOWN
automatic handoff = disabled
production path = CLI_RESUME_FALLBACK
```

No sandbox was widened, no global configuration was changed, and no blanket
approval handler was installed. A missing local fixture side effect is not
converted into a denial or success claim. It remains an evidence boundary.

Because no live approval request arrived, the optional controller-crash-while-
approval-pending case was not exercised and is not promoted to PASS.
