# v0.3 token and model-request benchmark

The benchmark ran the same short fixture prompt through normal `codex exec` and
a Snooze-owned App Server thread. It counted protocol-visible turn requests,
item notifications, wall time and token usage notifications. The authoritative
record is [results/v0.3/token-benchmark.json](results/v0.3/token-benchmark.json).

The current run observed one model turn and one model request in each path.
Token usage notifications were exposed by the App Server and token-related
usage was present in the normal JSONL stream. The fixture marker was not
produced, so this is telemetry and request-count evidence rather than a
successful workload comparison.

```text
TOKEN_TELEMETRY = PASS
TOKEN_SAVINGS = UNKNOWN
```

Wall time is not converted into token savings. A valid savings comparison needs
the same fixture to execute successfully in both paths and stable token and
model-request accounting across repeated runs.
