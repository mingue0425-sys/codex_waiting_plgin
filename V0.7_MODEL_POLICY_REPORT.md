# v0.7 Luna-only Model Policy Report

Every live v0.7 experiment is explicitly pinned to GPT-5.6 Luna with medium reasoning effort. The real App Server command is `codex -m gpt-5.6-luna -c 'model_reasoning_effort="medium"' app-server --stdio`; direct CLI execution uses the equivalent `codex exec -m gpt-5.6-luna -c 'model_reasoning_effort="medium"' ...`. Installed schema evidence for `thread/start.model`, `turn/start.model`, and `turn/start.effort` is recorded in [V0.7_RUNTIME_SOURCE_TRACE.md](V0.7_RUNTIME_SOURCE_TRACE.md).

Before a candidate tool call, the controller runs a no-tool attestation turn and records requested, runtime, thread and turn model values. Approval review is user-owned, multi-agent delegation is disabled, and fallback/reroute/non-Luna activity fails closed. The mandatory pre-probe log is emitted by each live v0.7 probe.

```text
model_policy = LUNA_ONLY
requested_model = gpt-5.6-luna
runtime_reported_model = gpt-5.6-luna
thread_model = gpt-5.6-luna
turn_model = None
observed_model = gpt-5.6-luna
reasoning_effort = medium
model_attestation = FAIL
experiment_valid = False
fallback_detected = False
auto_review_model_override = None
review_model = user
delegated_model = None
subagent_policy = DISABLED
subagent_calls = []
non_luna_model_calls = 0
attestation_reasons = ['missing_turn_model']
```

`LUNA_MODEL_ATTESTATION=FAIL` and `EXPERIMENT_VALID=False`. The installed runtime reported `gpt-5.6-luna` for the runtime and `gpt-5.6-luna` for the thread, but the turn model field was `None`. A missing turn field makes the live sample invalid; no candidate fixture command was started.

No historical pre-policy live result is used as v0.7 evidence. A missing or non-Luna runtime value remains invalid and never becomes handoff, sandbox, approval, latency or benchmark proof. Production selection remains `CLI_RESUME_FALLBACK`.
