# v0.3 live thread report

Track A inspected the running ChatGPT/Codex Desktop process tree, standard
descriptor type labels and public `codex app-server` help. The Desktop process
had an App Server child. The observed child used the default stdio transport,
and public help exposed no supported external attach or reconnect method.

```text
DESKTOP_LIVE_ATTACH = FAIL
EXTERNAL_DESKTOP_ATTACH = FAIL
DESKTOP_UI_REFLECTION = UNKNOWN
```

The probe did not open another process's descriptors, duplicate descriptors,
read memory, inject a debugger, extract credentials or mutate a thread. Its
output is [results/v0.3/desktop-attach.json](results/v0.3/desktop-attach.json).

The installed schema and help fixture is [results/v0.3/schema-probe.json](results/v0.3/schema-probe.json),
with stable and experimental JSON/TypeScript files under
`results/v0.3/app-server-schema/`. A schema method is treated as a protocol
surface, not evidence that it controls the Desktop live runtime.

Track B created a disposable Snooze-owned thread, observed `thread/started`,
`turn/started`, command execution items, `turn/completed` and token usage
notifications. Durable thread resume after an owned App Server restart passed
in the crash/reconnect probe. Desktop UI reflection remains UNKNOWN because no
supported external receiver was available.
