# v0.3 handoff E2E report

The model-backed E2E used a temporary fixture workspace and asked the owned
App Server thread to run an explicit `codex-snooze submit --handoff-after 10`
command. The protocol trace observed a terminal `commandExecution` item and a
completed first turn. The durable job store did not contain a result before
probe cleanup, so the complete chain remains unproven:

```text
E2E_LONG_JOB_HANDOFF = UNKNOWN
tool_execution_observed = true
turn_start_requests = 1
same_thread_continuation = false
job_survival = unobserved
```

The first attempt also showed that a direct model command can produce a
completed terminal item without a durable Snooze result. This is retained as
evidence rather than converted into a success claim. See
[results/v0.3/app-server-e2e.json](results/v0.3/app-server-e2e.json).

The explicit experimental `process/spawn` fixture did launch a two-second
Python process and observed its marker and `process/exited` event. That proves
the native process lifecycle for the safe fixture only. It does not prove that
a model-created shell item uses that backend or preserves normal approval and
sandbox semantics.

The local handoff race probe passed partial JSONL handling, owned thread
registry, event marker duplicate protection, default server-request rejection,
crash detection and response-loss retry state. `SENT_UNCONFIRMED` remains an
at-least-once state; the protocol exposes no client idempotency key, so exactly
once is not claimed.

Automatic continuation stays disabled until a repeatable model-backed run
proves one command, a durable exit code, no model polling during the wait, one
completion event and a same-thread continuation that does not rerun it.
