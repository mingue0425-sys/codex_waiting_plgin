# Codex Snooze v0.6 handoff E2E

The v0.6 production gate requires all of the following for either candidate:

```text
command integrity
sandbox parity
approval parity
process identity
p100 handoff latency <= 10 seconds across 30 runs
job survival after ownership transfer
model idle during the wait
correlated completion detection with exit code
same-thread continuation
```

## Evidence

The live A/B sample requested one normal thread run per candidate. Both runs
produced normal command item lifecycle events and process identifiers, but the
fixture side effects were absent and the background-terminal list was empty.
The 30-run p100 sample requirement was therefore not met, and no handoff
latency sample was recorded.

No continuation was attempted because ownership was not proven. This prevents
a second execution from being confused with continuation evidence. The
artifacts are [handoff-latency.json](results/v0.6/handoff-latency.json),
[model-idle.json](results/v0.6/model-idle.json),
[process-survival.json](results/v0.6/process-survival.json),
[completion-detection.json](results/v0.6/completion-detection.json), and
[continuation.json](results/v0.6/continuation.json).

The local ownership race suite reports 100/100 single-owner claims and 100/100
expected rejections. The new crash matrix passes the durable pre/post-CAS
invariants but remains UNKNOWN for live native process survival, App Server
reconnect and completion during controller downtime. Existing v0.4 App Server
and controller crash-recovery artifacts remain PASS as historical supervisor
evidence; they do not prove v0.6 native ownership.

The resulting production path is `CLI_RESUME_FALLBACK`, with automatic native
handoff disabled.
