# Codex Snooze v0.4 continuation and recovery report

v0.4 routes a completion event only after a durable handoff marker, a terminal
job result and a recorded thread mapping exist. The continuation is an
explicit new turn on the same Snooze-owned App Server thread.

## Router behavior

`CompletionRouter` persists these states:

```text
CLAIMED -> STARTING -> SENT_UNCONFIRMED -> ACKED
                    \-> RETRY_WAIT
```

An existing `CLAIMED`, `STARTING` or `SENDING` event rejects a second claim.
`SENT_UNCONFIRMED` also rejects retry unless the caller supplies explicit
duplicate permission. The installed protocol does not provide a client
idempotency key, so delivery is at-least-once-compatible and exactly-once is
not claimed.

## Race evidence

Evidence: [results/v0.4/continuation-races.json](results/v0.4/continuation-races.json).

The 100-iteration race probe produced:

| Measure | Result |
|---|---:|
| Iterations passed | 100 |
| Continuation turns created | 100 |
| Duplicate claims rejected | 100 |
| Registry handoff entries | 100 |
| Thread corruption cases | 0 |
| Job reruns | 0 |
| Exactly-once status | `NOT_CLAIMED` |

The probe validates the durable claim guard and mapping behavior. It does not
turn the absence of a protocol idempotency key into an exactly-once claim.

## Process crash evidence

[results/v0.4/app-server-crash.json](results/v0.4/app-server-crash.json)
shows that killing the owned App Server after the marker left the supervisor
job alive, recorded `CRASHED`, resumed the durable thread after reconnect and
completed the continuation.

[results/v0.4/controller-crash.json](results/v0.4/controller-crash.json)
shows the corresponding controller failure case. A worker exited after the
durable checkpoint, a new controller recovered the pending completion and
completed the same-thread continuation.

Both probes pass their recovery conditions while retaining
`exactly_once=NOT_CLAIMED`.

## Observable model-idle boundary

The primary 12-second fixture run measured zero model activity between the
handoff and durable completion. Controller interrupt, turn-completion,
token-usage and rate-limit notifications are excluded from the model-activity
filter; actual turn/item activity remains visible. This is a measured idle
wait on the owned App Server, not an inference from elapsed wall time.
